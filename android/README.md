# LocalTube Android

Автономное приложение: сервер LocalTube ему не нужен. `yt-dlp` и `FFmpeg` встроены в APK через [youtubedl-android](https://github.com/JunkFood02/youtubedl-android), видео скачиваются и хранятся на устройстве.

Две сборки: `mobile` для телефонов и планшетов и `tv` для Android TV. Различаются только манифестом (в ТВ-версии признак `leanback` обязателен, иначе лончер и Play не считают приложение ТВ-приложением), код и функции одинаковые. `applicationId` тоже одинаковый, поэтому библиотека и настройки переносятся между сборками.

## Возможности

Каталог и навигация:

- Вкладки: Видео, Shorts, Каналы, Плейлисты, Мои
- Сортировка: новые, старые, по названию, по размеру, случайно
- Страница канала со списком видео и Shorts
- Поиск по локальной библиотеке
- Избранное, история просмотров, скрытие каналов

Плеер:

- Скорость 0.5x — 2x, перемотка на 10 секунд двойным касанием
- Возобновление с места, где остановились
- Субтитры, регулировка звука, полный экран, театральный режим
- Рекомендации и переход к следующему видео
- Управление с пульта: центральная кнопка — пауза, влево-вправо — перемотка
- Фоновое воспроизведение: звук продолжается при сворачивании, управление с экрана блокировки и наушников
- Картинка в картинке
- Эквалайзер: пресеты и усиление басов
- Локальная конвертация в другое качество и извлечение MP3 через FFmpeg
- Свои плейлисты и «Смотреть позже»
- Управление субтитрами: скачивание доступных дорожек и импорт своего файла

Загрузки:

- Выбор качества, включая 1080p и выше (раздельные потоки склеиваются с аудио)
- Приоритеты: высокий, обычный, низкий
- Пауза очереди, отмена, повтор упавших задач
- Прогресс со скоростью и оставшимся временем
- Очередь переживает перезапуск приложения
- Ссылку можно отправить в приложение через «Поделиться»
- Свои видео: добавление из файлов, превью берётся кадром из самого видео

Каналы:

- Баннер, аватар, описание и число подписчиков
- Синхронизация: показывает, какие видео канала ещё не скачаны, и добавляет выбранные в очередь
- Контейнер для пакетной загрузки: MP4, MKV или WEBM

Оформление:

- Три темы: тёмная, светлая, Frutiger Aero
- Адаптивная вёрстка: нижняя панель на телефоне, боковая на планшете и ТВ
- Число колонок в сетке зависит от ширины экрана
- Имя в шапке задаётся в настройках, как `username` в веб-версии

Чего нет по сравнению с настольной версией:

- PO Token и плагины bgutil: они требуют отдельного резидентного сервиса, на телефоне это нереалистично. Против «Sign in to confirm you're not a bot» остаются `player_client` и cookies
- Подключение к чужому LocalTube в сети: приложение только раздаёт свою библиотеку, но не открывает чужую
- Экспорт cookies прямо из браузера: на Android доступа к профилям браузеров нет, cookies импортируются файлом
- Отдельная настройка путей для каждой папки: есть только выбор между внутренней памятью и картой памяти
- Таб «Главная» на странице канала с блоком «Рекомендуемое»: в приложении сразу открывается список видео

## Локальная сеть

Приложение умеет раздавать библиотеку другим устройствам в той же сети: «Настройки» → «Локальная сеть» → «Раздавать по Wi-Fi». Там же показываются адрес (например `http://192.168.1.5:8733`), PIN и кнопка «Показать QR-код»: навести камеру проще, чем набирать адрес на чужом телефоне.

Гость открывает адрес в браузере, вводит PIN и получает доступ только к просмотру: каталог, страницы видео и каналов, поиск и сами файлы. Скачивать, удалять и менять настройки через веб нельзя — разрешения перечислены явным белым списком, как `GUEST_ENDPOINTS` в настольной версии.

Как устроен доступ:

- PIN шестизначный, генерируется при первом включении, кнопка «Новый PIN» отключает все впущенные устройства сразу
- Ключ устройства — HMAC-SHA256 от PIN на случайном секрете, хранится у гостя в cookie на 90 дней, на устройстве не хранится вовсе
- Не больше 10 попыток ввода за 5 минут с одного адреса
- Скрытые каналы гостю не видны ни в каталоге, ни по прямой ссылке на файл
- Порт настраивается (по умолчанию 8733); занятый порт показывается сообщением, а не приводит к падению
- QR рисуется на устройстве (`QrCode.kt`), наружу ничего не уходит — как `make_qr_png` в `access.py`

Раздача работает, пока приложение открыто, и по HTTP без шифрования: она рассчитана на домашнюю сеть, выставлять порт в интернет нельзя.

## Требования

Android 8.0 (API 26) и новее.

## Сборка

Нужны JDK 17 и Android SDK 35. Gradle wrapper в комплекте.

Имя задачи включает флейвор: задач вида `assembleDebug` без него не существует.

```bash
./gradlew assembleMobileDebug       # телефоны и планшеты, отладочная
./gradlew assembleTvDebug           # Android TV, отладочная
./gradlew assembleMobileRelease assembleTvRelease
./gradlew testMobileDebugUnitTest   # тесты
```

APK появятся в `app/build/outputs/apk/<флейвор>/<тип>/`. Для каждого флейвора собираются варианты для `arm64-v8a`, `armeabi-v7a`, `x86_64` (эмулятор) и универсальный.

Сборке нужно около 4 ГБ ОЗУ (`org.gradle.jvmargs` в `gradle.properties`): вариантов теперь восемь, и при меньшем размере кучи слияние dex падает с `OutOfMemoryError`. В логе это выглядит как невнятный сбой задачи `package<Флейвор><Тип>` без упоминания памяти.

### Проверка загрузки на устройстве

Юнит-тесты не проверяют сами yt-dlp и ffmpeg: это нативные процессы, а в JVM-тестах `returnDefaultValues` возвращает заглушки. Ошибку в аргументах или в окружении процесса поймает только запуск на устройстве или эмуляторе. Так нашлись две поломки, каждая из которых полностью отключала свою функцию:

- `--retry-sleep 1,10` — yt-dlp считает список через запятую синтаксической ошибкой и завершается, ничего не скачав, поэтому падала любая загрузка. Значение вынесено в `Engine.RETRY_SLEEP`.
- в `LD_LIBRARY_PATH` для ffmpeg была только папка `packages/ffmpeg/usr/lib`, а `libc++_shared.so` лежит в `packages/python/usr/lib` и нужен `librubberband.so` из состава ffmpeg. Линкер отказывался запускать процесс («CANNOT LINK EXECUTABLE»), из-за чего молча не работали пресеты качества, извлечение MP3 и создание превью. Путь собирает `Ffmpeg.joinLibraryPath`.

Оба значения закреплены тестами, но тест проверяет только формат строки: что процесс действительно стартует, показывает лишь запуск на устройстве.

Быстрый прогон на эмуляторе: поставить APK для `x86_64`, отправить ссылку через «Поделиться» и посмотреть результат в `queue.json`.

```bash
adb install -r -t app/build/outputs/apk/mobile/debug/app-mobile-x86_64-debug.apk
adb shell am start -a android.intent.action.SEND -t text/plain \
    --es android.intent.extra.TEXT '<ссылка>' \
    -n io.github.kiramorano.localtube/.MainActivity
adb shell run-as io.github.kiramorano.localtube cat files/queue.json
```

Первый запуск дольше обычного: распаковываются Python и ffmpeg. Если задача упала, текст ошибки yt-dlp целиком лежит в поле `error` в `queue.json` — там он подробнее, чем в интерфейсе.

Функции ffmpeg проверяются на уже скачанном видео: «Извлечь MP3» и любой пресет в меню «Качество» на странице видео. Рядом с `video.mp4` должны появиться `audio.mp3` и `video_<пресет>.mp4`.

### Подпись

Если рядом лежит `app/keystore.jks`, release подписывается им, пароли берутся из переменных окружения `LT_STORE_PASSWORD`, `LT_KEY_ALIAS`, `LT_KEY_PASSWORD`. Файл keystore в репозиторий не попадает.

Без keystore release подписывается отладочным ключом. Локально это удобно, но собирать так публичные релизы нельзя: Gradle создаёт отладочный ключ заново на каждой чистой машине, поэтому APK разных сборок окажутся подписаны разными ключами. Android не поставит такое обновление поверх предыдущей версии, а переустановка удаляет данные приложения вместе со скачанными видео.

Сборка в GitHub Actions берёт ключ из секретов репозитория:

| Секрет | Содержимое |
| --- | --- |
| `LT_KEYSTORE_B64` | `keystore.jks` в base64 |
| `LT_STORE_PASSWORD` | пароль хранилища |
| `LT_KEY_ALIAS` | имя ключа |
| `LT_KEY_PASSWORD` | пароль ключа |

Свой ключ создаётся один раз:

```bash
keytool -genkeypair -keystore app/keystore.jks -alias localtube \
        -keyalg RSA -keysize 4096 -validity 10950 \
        -dname "CN=LocalTube, O=LocalTube, C=RU"
base64 -w0 app/keystore.jks   # значение для LT_KEYSTORE_B64
```

Ключ надо сохранить в надёжном месте: без него обновить уже установленные копии приложения не получится.

Если путь к проекту содержит не-ASCII символы, для сборки может понадобиться каталог кэша без них:

```bash
./gradlew -PbuildDir=C:/lt-build test
```

## Хранение данных

По умолчанию всё лежит во внутренней памяти приложения (`filesDir`), раскладка повторяет серверную версию:

```
videos/<Автор>/<id>/video.mp4 + info.json + thumbnail.jpg
user_videos/<id>/video.<ext> + meta.json
playlists/<Название>/playlist.json
avatars/<Автор>.jpg           аватары каналов
avatars/banners/<Автор>.jpg   баннеры каналов
userdata.json        избранное, история, скрытые каналы, позиции просмотра, плейлисты
queue.json           очередь загрузок
cookies.txt          cookies для YouTube
```

В настройках можно перенести библиотеку на карту памяти. Уже скачанное при этом остаётся на прежнем месте — копировать десятки гигабайт из приложения слишком рискованно, перенести файлы нужно вручную. `cookies.txt` и личные данные всегда остаются во внутренней памяти: на съёмном носителе они пропадут вместе с картой.

JSON пишется атомарно, с копией предыдущей версии в `.bak`: сбой записи не приводит к потере данных.

Готовые сборки — во вкладке [Releases](https://github.com/kiramorano/LocalTube/releases).
