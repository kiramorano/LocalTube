## Браузерные тесты (Playwright)

Нужен запущенный сервер:

```bash
python app.py
```

Затем в отдельном терминале:

```bash
cd tests/browser
npm install
npx playwright install chromium
npm test
```

`npm test` прогоняет все 22 скрипта. Отдельные группы: `npm run queue`,
`npm run channel`, `npm run mobile`, `npm run settings`,
`npm run collections`, `npm run player`, `npm run network`, `npm run theme`,
`npm run audit`.

Скрипты, которые меняют данные (`userdata-verify.cjs`, `hidden-channels.cjs`,
`collections-ui.cjs`, `lan-access.cjs`), запускать против рабочего сервера
нельзя: они чистят историю, избранное и скрытые каналы, создают плейлисты и
меняют PIN. Такой запуск уже оставил лишнюю запись в `userdata.json`
пользователя. Поэтому они требуют изолированного сервера: `serve_test.py`
отдаёт `/api/test-mode` со списком изолированных файлов, и без этого признака
скрипт отказывается работать (`require-test-server.cjs`).

Для проверок поднимите отдельный
экземпляр: `python tests/browser/serve_test.py` (порт задаётся `LT_PORT`,
по умолчанию 5004), затем `LT_BASE=http://127.0.0.1:5004 npm test`. Тестовый
сервер изолирует очередь, `config.json` и `userdata.json` во временные файлы:
проверки раздела «Хранение» сохраняют пути через API и иначе увели бы настоящую
библиотеку пользователя в временную папку, а проверки плейлистов создали бы
коллекции в его настоящих данных, а проверки сети сменили бы его PIN.
Отключается переменными `LT_USE_REAL_QUEUE`, `LT_USE_REAL_CONFIG`,
`LT_USE_REAL_USERDATA` и `LT_USE_REAL_ACCESS` со значением `1`.

Адрес прослушивания задаётся переменной `LT_HOST` (по умолчанию `127.0.0.1`).
Для проверки гостевого режима нужен `LT_HOST=0.0.0.0`: с `127.0.0.1` любой
клиент считается владельцем, и роль гостя не воспроизвести.

`queue-verify.cjs` проверяет доступность раздела «Очередь», видимость карточек
в тёмной и светлой темах и остановку опроса вне раздела. `picker-verify.cjs`
проверяет выбор конкретных видео, качества и формата перед добавлением в
очередь.

`url-download-ui.cjs` проверяет загрузку по ссылке из хедера главной: пустое
поле и текст вместо ссылки в очередь не уходят, выбранное качество попадает в
`format_id` (а при «Максимум» не передаётся вовсе), Enter запускает загрузку,
после успеха поле очищается и открывается очередь, ошибка сервера показывается
пользователем и ссылка остаётся в поле для повтора. Отдельно проверяется
мобильная ширина: поле ввода не должно сжимать гамбургер до нулевой ширины —
из-за этого меню на телефоне перестаёт нажиматься.

`settings-sections.cjs` проверяет разделы настроек и папки хранения: вкладки
переключаются, элементы соседних разделов при этом действительно скрыты, а не
просто присутствуют в разметке, выбранный раздел запоминается. Отдельно
проверяется полный список элементов управления в каждом разделе: при разбиении
на вкладки кнопка экспорта cookies уже оказывалась в закрытом разделе, и клик
по ней перестал проходить. По путям: поля заполняются с сервера, показывается
абсолютный путь, пустое значение не отправляется, недоступный диск даёт
понятную ошибку и путь остаётся в поле, успешное сохранение создаёт папку и
применяется без перезапуска, кнопка сброса возвращает значения по умолчанию.
На ширине 390px проверяется отсутствие горизонтальной прокрутки: вкладки
иначе растягивают страницу.

`quality-switch.cjs` проверяет выбор качества 144p-2160p в живом плеере.
Ступени идут от высокого качества к низкому, готовое качество переключает файл и
сохраняет позицию просмотра, недоступное запускает пересборку и показывает
процент, по готовности пункт перестаёт предлагать пересборку, а гостю
недоступные ступени не показываются вовсе. Ответы `/api/quality` и
`/api/convert` подменяются: настоящая пересборка идёт минутами, а сам FFmpeg
покрыт pytest. Скрипт нашёл два дефекта, которых проверки разметки не видели:
меню из одиннадцати ступеней не влезало в высоту плеера — верхние пункты
выезжали за его край, попадали под содержимое страницы и не нажимались; и общий
обработчик «клик вне меню» закрывал меню качества при выборе ступени, потому что
оно лежит рядом с меню настроек, а не внутри него, — прогресс пересборки
становилось не видно. Позже тот же скрипт нашёл ещё два: смена `src` возвращала
скорость воспроизведения к 1x, тогда как кнопка продолжала показывать «2x», и
атрибут `autoplay` на элементе `<video>` запускал остановленный ролик заново —
пауза превращалась в воспроизведение с середины. Отдельная проверка следит за
включёнными субтитрами: сами по себе они переживают смену источника, потому что
элементы `<track>` остаются в DOM, но проверка ловит регресс, если дорожки
начнут пересоздаваться. Дорожки для неё подделываются: в библиотеке субтитров
может не быть вовсе.

`sidebar-collapse.cjs` проверяет кнопку сворачивания боковой панели. На
широком экране панель закреплена: нажатие убирает её за край и контент занимает
освободившееся место, затемнение при этом не включается (перекрывать нечего),
повторное нажатие возвращает панель, `aria-expanded` отражает состояние. На
страницах без закрепления (`/upload`) панель остаётся выдвижной, на узком экране
она выезжает поверх контента с затемнением. Дефект, который скрипт нашёл: на
десктопе кнопка только затемняла экран, а панель не двигалась — правило
`.sidebar-drawer { left: 0 }` из медиазапроса шаблона перебивало класс
состояния.

`language-switch.cjs` проверяет переключение языка интерфейса. По умолчанию
интерфейс русский; выбор английского в настройках сохраняется в cookie
`lt_lang`, страница перерисовывается, и на других страницах язык сохраняется;
возврат на русский работает. Отдельно проверяется, что английская страница не
содержит русских подписей — данные библиотеки (названия видео, имена каналов,
буква аватара) из проверки исключены, их не переводят. Скрипт нашёл три дефекта:
разметка `t()` внутри JSON-литерала профиля ломала `JSON.parse` и оставляла
страницу без обработчиков; словарь, приходивший отдельным запросом, не успевал к
первой отрисовке; и главное — Jinja сворачивала `{{ 'Строка'|t }}` при
компиляции шаблона, запекая язык первого рендера, поэтому страница, впервые
открытая на русском, не переводилась до перезапуска сервера.

`collections-ui.cjs` проверяет свои плейлисты в живом браузере: плейлист
создаётся из бокового меню и появляется в нём, название с кавычкой и `<b>` не
превращается в разметку, пустое название отклоняется. На странице видео
открывается окно выбора (оно скрыто через `opacity`, а не `display`, поэтому
проверяется класс, а не видимость), галочка добавляет видео и счётчик растёт
ровно на единицу, «Смотреть позже» создаётся при первом обращении, новый
плейлист из окна сразу получает текущее видео, закрытое окно не перехватывает
клики. На странице плейлиста: переименование без перезагрузки, снятие видео
кнопкой внутри ссылки не уводит на страницу видео, удаление возвращает на
главную, у встроенного «Смотреть позже» кнопок правки нет, неизвестный
плейлист даёт 404. Отдельно проверяется просмотр по порядку: кнопка
«Смотреть» добавляет `?collection=`, страница показывает место в списке и
ссылку назад, а событие окончания видео открывает следующий ролик с тем же
параметром (проверяется только в браузере: разбор текста шаблона подмену
`at + 1` на `at` не отличает). Названия помечаются метой прогона, а созданное
убирается в конце — в том числе при падении: иначе повторный запуск находил
плейлисты от прошлого раза и проверки счётчиков врали, а прерванный прогон
однажды оставил два плейлиста, которые следующий запуск счёл своими.

Этот скрипт требует запуска через `serve_test.py`: он изолирует
`userdata.json`, иначе проверки создали бы плейлисты в настоящих данных
пользователя.

`lan-access.cjs` проверяет раздел «Сеть» и гостевой режим. По владельцу:
адреса подставляются и копируются, PIN из шести цифр, тумблер меняет подпись,
QR-код действительно загружается картинкой и скрывается повторным нажатием,
смена PIN требует подтверждения и при отказе не выполняется, чужой сервер
добавляется, проверяется и удаляется, адрес с мусором отклоняется.

Гостевую часть скрипт выполняет только если задан `LT_LAN` — адрес того же
сервера в локальной сети (`LT_LAN=http://192.168.0.22:5012`), а сам сервер
поднят на `0.0.0.0`. Проверяется, что гостю не показаны кнопки владельца, что
`/settings` и `/api/userdata` отвечают 403, что PIN не попадает в разметку, что
вход по PIN даёт права и выход их снимает, а выключенный тумблер закрывает
доступ полностью. Отдельно проверяется, что избранное гость хранит в своих
ключах `localStorage` и не пишет в ключи владельца: именно так нашёлся дефект —
гость складывал избранное в `lt_favorites`, и при первом входе по PIN перенос
старых данных отправлял его на сервер, подмешивая к избранному владельца.

`theme-verify.cjs` проверяет пять тем (`dark`, `light`, `midnight`, `glass`,
`frutiger-aero`) на главной и в настройках: тема применяется до первой
отрисовки, нет прозрачного текста, контраст в норме, нет горизонтальной
прокрутки, склейка поиска не распадается, нет ошибок в консоли, обои
запрашиваются только у Frutiger Aero. `theme-shots.cjs` снимает скриншоты
всех тем в `tests/browser/shots/themes/`.

`about-contrast.cjs` проверяет читаемость вкладки «О канале» во всех пяти
темах: считает контраст подписей, значений, тегов и ссылки по WCAG AA. Фоны
плиток в `glass` и `frutiger-aero` полупрозрачные, поэтому скрипт складывает
цепочку слоёв — белый с alpha .18 над тёмным фоном даёт тёмный результат, и
подсчёт по «ближайшему непрозрачному» родителю врал. `frutiger-aero` делает
текст белым на светлых обоях и добивается читаемости обводкой `text-shadow`,
а не контрастом фона, поэтому для неё проверяется наличие тени.

`cookies-browser-ui.cjs` проверяет выбор браузера и кнопку экспорта cookies в
настройках: список подгружается с сервера, отсутствующие браузеры помечены и
недоступны, ошибка сервера доходит до пользователя. Отдельно проверяется, что
сообщение об успехе остаётся на экране: обновление общего статуса выполняется
в том же обработчике и раньше затирало его. Ответ `/api/auth/status` при этом
намеренно задерживается, иначе гонка проявляется через раз. Сам импорт
перехватывается, настоящий `cookies.txt` не перезаписывается.

`userdata-verify.cjs` проверяет перенос данных из localStorage на сервер и
доступность избранного с другого устройства. `hidden-channels.cjs` проверяет
серверную фильтрацию скрытых каналов и кнопку на странице канала. Оба
временно очищают разделы пользовательских данных, поэтому требуют
изолированного сервера и сами это проверяют.

Скриншоты складываются в `tests/browser/shots/` и не попадают в git.
Все обращения к YouTube и TikTok в этих тестах перехватываются, поэтому сеть не нужна.

## Мобильная вёрстка

`mobile-audit.cjs` меряет страницы веб-версии на эмуляции телефона:
горизонтальный скролл, блоки за краем экрана, перекрытые элементы. Ложные
срабатывания отфильтрованы (скрытые предки, уехавший за экран fixed-сайдбар,
горизонтальные полки).

`lan-mobile-audit.cjs` меряет то же самое у гостевых страниц
Android-приложения. Они собираются в Kotlin (`LanPages.kt`), а не из шаблонов
Flask, поэтому проверяются отдельно: сначала юнит-тест `LanPagesDumpTest`
выгружает готовый HTML, затем скрипт открывает его как `file://`.

```powershell
cd android
$env:LT_DUMP_DIR = "$env:TEMP\lanpages"
.\gradlew.bat --rerun-tasks :app:testMobileDebugUnitTest --tests '*LanPagesDumpTest*'
cd ..\tests\browser; node lan-mobile-audit.cjs
```

Без `LT_DUMP_DIR` выгрузка не делает ничего, поэтому обычный прогон тестов не
создаёт лишних файлов. Найденные так поломки закреплены юнит-тестами в
`LanPagesMobileTest`: тап-цели ниже 44px, вертикальные Shorts во всю ширину
экрана (одна обложка занимала 81% высоты), шрифт полей меньше 16px (Safari на
iOS зумит страницу при фокусе) и потеря запроса в поле после поиска.
